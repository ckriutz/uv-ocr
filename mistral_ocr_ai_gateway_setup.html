Customer setup guide

Run Mistral OCR through Microsoft Foundry AI Gateway

Configure a custom API in the API Management instance behind AI Gateway, authenticate callers with an APIM subscription key, authenticate APIM to Foundry with managed identity, and verify every layer before running OCR.

2. Custom APIM APIMatches the /mistral-ocr API suffix.
3. Managed identityAPIM obtains a Foundry backend token.
4. Mistral OCRReceives /providers/mistral/azure/ocr.

1

Choose the correct gateway route

The provider-specific Mistral OCR operation needs the custom APIM API.

EndpointUseResult for this notebook
https://<gateway>.azure-api.net/<foundry-project>Foundry-generated standard model APIDo not use for this OCR route
https://<gateway>.azure-api.net/mistral-ocrCustom passthrough API targeting the Foundry resourceUse this value
Why: the generated project API routed the provider-specific OCR path to an Azure ML-style backend and returned 404 NOT FOUND. The custom API explicitly targets the resource endpoint that exposes Mistral OCR.
2

Collect the required values

Record these before editing APIM.

  • Foundry resource endpoint: https://<resource>.services.ai.azure.com, without the OCR path.
  • OCR deployment name: the exact name under Foundry Models + endpoints.
  • AI Gateway APIM instance: shown under Foundry Manage → AI Gateway.
  • Permissions: enough access to edit APIM APIs/policies and assign RBAC on the Foundry resource.
3

Enable Foundry AI Gateway

Foundry AI Gateway uses Azure API Management behind the scenes.

  1. In the new Foundry portal, open the resource.
  2. Go to Manage → AI Gateway → Add AI Gateway.
  3. Create or select an eligible APIM instance.
  4. Wait for status Enabled.
  5. For an existing project, open the gateway and select Add project to gateway.
Keep the generated Foundry API. The custom OCR API created below is an additional API in the same APIM instance.
4

Give APIM a backend identity

Use managed identity instead of storing a Foundry credential in APIM.

  1. Open the APIM resource in Azure Portal.
  2. Go to Security → Managed identities and enable the system-assigned identity.
  3. Open the Foundry resource's Access control (IAM).
  4. Assign Cognitive Services User to the APIM managed identity.
  5. Wait several minutes for RBAC propagation.
5

Create the custom Mistral OCR API

Create this in the APIM instance associated with AI Gateway.

  1. Go to APIM → APIs → Add API → HTTP.
  2. Set Display name to Mistral Document OCR.
  3. Set Web service URL to the Foundry resource base endpoint.
  4. Set API URL suffix to mistral-ocr.
  5. Add a POST operation with URL template /providers/mistral/azure/ocr.
Client URLhttps://<gateway>.azure-api.net/mistral-ocr/providers/mistral/azure/ocr
Backend URLhttps://<resource>.services.ai.azure.com/providers/mistral/azure/ocr
6

Add the API-level policy

Apply it at Mistral Document OCR → All operations, not globally.

Open Design → Inbound processing → Policy code editor and use the following policy. Replace the backend placeholder.

<policies>
  <inbound>
    <base />
    <set-backend-service
      base-url="https://<foundry-resource>.services.ai.azure.com" />
    <authentication-managed-identity
      resource="https://ai.azure.com"
      ignore-error="false" />
  </inbound>
  <backend>
    <base />
  </backend>
  <outbound>
    <base />
  </outbound>
  <on-error>
    <base />
  </on-error>
</policies>
Inspect the POST operation's own policy too. Remove any operation-level set-backend-service that points to an Azure ML or project endpoint, because it can override the API-level backend.
7

Create client access to the custom API

Keep Subscription required enabled.

  1. Go to APIM → Subscriptions → Add subscription.
  2. Choose API scope and select Mistral Document OCR.
  3. Create it in Active state.
  4. Copy either generated primary or secondary key.
  5. Under the custom API's settings, confirm the subscription header name. New custom APIs normally use Ocp-Apim-Subscription-Key.
Secret handling: store the key only in the local .env. Never paste it into a notebook, screenshot, email, or source control. Rotate either key immediately if exposed.
8

Configure the local environment

Copy .env.example to .env, then fill in real values.

AZURE_FOUNDRY_ENDPOINT=https://<resource>.services.ai.azure.com
AZURE_MISTRAL_OCR_DEPLOYMENT=mistral-ocr-4-0
AZURE_MISTRAL_OCR_API_KEY=

AZURE_AI_GATEWAY_ENDPOINT=https://<gateway>.azure-api.net/mistral-ocr
AZURE_AI_GATEWAY_SUBSCRIPTION_KEY=<custom-API subscription key>
AZURE_AI_GATEWAY_KEY_HEADER=Ocp-Apim-Subscription-Key
AZURE_AI_GATEWAY_AUTH_MODE=gateway_managed_identity
  • Only one AZURE_AI_GATEWAY_ENDPOINT assignment should exist.
  • Do not append /providers/mistral/azure/ocr; the notebooks append it.
  • Restart the notebook kernel after changing .env.
9

Verify before processing a document

Run mistral_ocr_ai_gateway_diagnostics.ipynb from the beginning.

  1. Run uv sync, then uv run jupyter lab.
  2. Restart the kernel and run all diagnostic cells in order.
  3. The no-key probe should return a gateway 401; this is expected.
  4. The key probe with an empty body should return 400 or 422; this proves routing and authentication reached payload validation.
  5. Run the final real OCR request and expect 200.
ResultLikely fix
401 missing subscription keyUse the header named in WWW-Authenticate; confirm key and subscription scope.
Backend 401Check the managed-identity policy audience and effective policy scope.
Backend 403Grant the APIM identity Cognitive Services User on Foundry.
Azure ML-style 404 NOT FOUNDReplace the backend with the services.ai.azure.com resource endpoint and remove policy overrides.
400/422 for {}Success: the request reached OCR validation.
TCP timeoutCheck APIM availability, DNS, public/private networking, VPN, firewall, and proxy.
When diagnostics reach payload validation, the gateway configuration is ready for the real document request.
